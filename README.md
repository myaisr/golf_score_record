# ROUNDNOTE

ホール終了後に打数とミスを記録し、ラウンド終了後に目標との差分を確認するゴルフ記録Webアプリです。HTML・CSS・JavaScriptで動作し、ビルド、ログイン、サーバー側DBは不要です。

## 起動・公開

Node.jsで起動します。

```bash
node scripts/preview.mjs
```

またはPythonの静的サーバーを使います。

```bash
python -m http.server 8000 --bind 127.0.0.1
```

`http://localhost:8000/` を開いてください。PWAはlocalhostまたはHTTPSで動作します。

GitHub Pagesでは **Settings → Pages → Deploy from a branch → main / (root)** を指定します。`index.html`、`app.js`、`roundnote-core.js`、`app.css`、`sw.js`、マニフェスト、アイコンを同じ階層で公開してください。Excel用PythonスクリプトはPages上では実行せず、PCで使用します。

更新後はオンラインで再読み込みしてください。初回のファイル保存が完了するとオフラインで入力・集計・PNG保存・JSON出力できます。iPhoneではホーム画面への追加後、そのアイコンから一度オンラインで開き、機内モードで開き直せることを事前に確認してください。

## 入力とラウンド終了

- 打数は「50y以内まで」「50y以内 → ON」「パット」の3項目です。選択済みの数字を再タップすると未入力に戻せます。大きい値は `− / ＋` で調整します。
- 未入力は `null`、記録した0打は `0` です。3項目すべてを入力すると、そのホールの打数が確定します。
- 「50y超からON」では、50y以内の打数を0にします。「50y以内まで」には直接ONまでの全打数を記録します。直接ON後に50y以内の打数を正の数に訂正すると、直接ONを解除します。
- OBは「ティーショット」「2打目以降」の回数を記録します。罰打は3項目の該当する打数に含め、OB欄ではスコアに再加算しません。
- 振り返りは任意です。ティーの「左・まっすぐ・右」は相互排他で、「ショート」は独立して併用できます。ショート単独も記録できます。チョロ・ダフリなど、著しい飛距離不足はショートに含めます。
- 使用クラブは「ドライバー／ウッド・ユーティリティ／アイアン／ウェッジ」の任意4択です。選択済みのボタンを再タップすると解除します。`teeClub` は `driver / wood_ut / iron / wedge` または未記録の `null` で保存し、この項目のない旧JSONも復元できます。Excelのホール別記録には「ティー使用クラブ」列を追加します。PNGでは `1W / W/UT / I / WG` と略記します。
- 50y以内の振り返りは方向・ダフリ・トップを複数選択できます。未記録と「ミスなし」は区別します。

ラウンド中は現在のホールの打数と入力済みホール数だけを表示し、累計スコア、OUT/IN小計、累計対Parを表示しません。「集計」を開いても、終了操作までは累計を表示しません。履歴一覧にもスコアを表示しません。

18Hの「ラウンド終了」、または集計画面の「ラウンドを終了して集計」で結果を表示します。未入力がある場合は確認後に途中終了できます。結果の「記録を再開」でラウンド中に戻すと、累計の表示を再び隠します。

## 結果と目標設定

結果には総スコア、OUT/IN、対Par、目標との差分、OB内訳、50y以内の2打以上率、直接ON、ティーショットの傾向、ホール別スコアカードを表示します。

「目標設定」で以下を変更・保存できます。設定はアプリ全体で共有し、過去のラウンドにも現在の目標を使用します。

| 指標 | 初期目標（18H） | 差分の良否 |
| --- | --- | --- |
| 総スコア | 99打以下 | 実績−目標が0以下 |
| 50yまでの打数 | 40打以下 | 実績−目標が0以下 |
| OB回数 | 2回以下 | 実績−目標が0以下 |
| 50y以内からの2打以上率 | 30%以下 | 実績−目標が0pt以下 |
| パット数 | 36打以下 | 実績−目標が0以下 |
| ボギーオン以内率 | 12H以上 / 18H（約66.7%） | 実績−目標が0pt以上 |

各目標は分析用の初期値です。指標の目標値を足して総スコア目標を作ることはありません。

「18H / OUT / IN」で比較範囲を切り替えます。OUT/INの打数・OB目標は18Hの半分です。総スコアの整数の端数はOUTへ配分し、初期値99打ならOUT50打、IN49打になります。2打以上率の目標は共通、ボギーオン目標は18Hのホール数を率に換算します。

途中終了では、実績は入力完了分だけを表示します。総スコア・50yまで・OB・パットの目標差分は対象の18Hまたは9Hが揃うまで「入力不足」とし、達成・未達を判定しません。率は対象がある場合に計算し、分母が0なら「対象なし」です。

### 指標の定義

- **打数・対Par・ボギーオン・3パット・アプローチ成績**：3項目すべて入力したホールを対象にします。ボギーオン以内は `long + short <= par - 1` です。
- **50y以内からの2打以上率**：入力完了ホールのうち、直接ONではなく `short >= 1` のホールが分母、そのうち `short >= 2` のホールが分子です。結果にはミス回数と対象回数も表示します。直接ONと未入力ホールは分母に入りません。
- **直接ON率**：入力完了ホールのうち `direct = true` の割合です。参考指標として表示し、必須の目標は設けていません。従来の50y以内からONまでの合計打数は記録・詳細表に残しています。
- **ティー方向別率**：方向を記録したホールが分母です。ショート単独のホールは方向別率の分母に入りません。
- **ティーショート率**：ショートの有無が分かり、方向またはショートを記録したホールが分母、ショートを選択したホールが分子です。ティー結果を全く記録していないホールと、旧記録でショート有無が不明なホールは分母に入りません。
- **OB回数**：入力したすべてのOB回数を集計します。ティーOBの左・右・その他は、そのホールのティー方向に回数を振り分けます。まっすぐ・方向未記録・ショート単独は「その他」です。方向ミスとOBを同一視しません。
- **50y以内の振り返り**：任意の記録をした、直接ONではないホールが分母です。複数選択の各件数は、そのミスが出たホール数です。

同一ホールの複数OBは、そのホールに記録した1方向にまとめて分類します。打ち直しごとの方向までは記録していません。ティー結果には方向と独立したショートしか入力しないため、ショート率の分母も上記の記録範囲に限られます。

### 結果PNG

「画像を保存」から、分析とスコアカードを2枚のPNGとして保存できます。各画像は1200×1600pxです。目標比較、OB内訳、アプローチ成績、OUT/IN比較を分析画像にまとめ、18Hの詳細はスコアカードに残します。

## ラウンド履歴・JSONバックアップ

### 作業フォルダ内の保存先

- `backups/`：アプリから出力したJSONを保存します。
- `outputs/`：取り込んだExcelを保存します。

両フォルダ全体と、作業フォルダ内のJSON・Excelファイルは `.gitignore` で除外しています。ルート直下に置いたJSONも対象です。これらの記録はGitHubには追加されません。

「新規ラウンド」では現在の記録を残して新しいIDのラウンドを作ります。途中のラウンドも履歴から開けます。履歴は端末内に保存し、クラウド同期は行いません。

1. 「履歴」→「JSON出力」で全ラウンド・現在の目標を保存します。通常のファイル名は `roundnote-backup-YYYY-MM-DD.json` です。
2. 別端末や保存データを戻すときは「履歴」→「JSON復元」でファイルを選びます。
3. 復元は既存データとのマージです。新しいIDを追加し、同一IDは `updatedAt` が新しい場合だけ更新します。同時刻・古い記録では上書きしません。ファイルにない既存ラウンドも保持します。
4. 既存の記録がある場合、現在選択しているラウンドと目標設定は維持します。空の初期状態では、バックアップの選択ラウンドと目標を引き継ぎます。

復元可能なJSONは15MiB（画面表記15MB）以下、最大2000ラウンドです。スキーマ・ID・打数・ホール数などを検証し、保存が成功してから読み込んだデータへ切り替えます。検証エラーや容量不足で既存データを置き換えません。件数上限以内でも、端末の保存容量によって保持できる件数は異なります。

### 保存形式と移行

- 通常の保存キー：`roundnote-golf-v2`
- プレビューの保存キー：`roundnote-golf-ui-preview-v2`
- スキーマ：`schemaVersion: 2`

新しい保存キーがなければ、旧キー `roundnote-golf-v1`（プレビューは `roundnote-golf-ui-preview-v1`）の単一ラウンドを読み込みます。旧キーは削除・上書きせず、変換後の記録を次の保存からv2キーへ保存します。旧 `tee: "good"` は `"straight"` に変換します。旧記録で `teeShort` がない場合は不明を表す `null` とし、ショートなしとはみなさずショート率の分母から除外します。明示した真偽値は維持し、新規ホールでは `false` を初期値にします。旧18H入力完了データは終了済みとして移行します。旧形式のJSONとバージョン1のJSONも復元できます。

以下は構造の抜粋です。実際の `holes` には18件が必要で、この1ホールだけの抜粋は復元ファイルとして使用できません。

```json
{
  "schemaVersion": 2,
  "exportedAt": "2026-11-01T03:00:00.000Z",
  "currentRoundId": "round-example",
  "goals": {
    "score": 99,
    "long": 40,
    "ob": 2,
    "approachRate": 30,
    "putts": 36,
    "bogeyOnHoles": 12
  },
  "rounds": [{
    "id": "round-example",
    "date": "2026-11-01",
    "place": "ゴルフ場名",
    "active": 0,
    "finished": false,
    "createdAt": "2026-11-01T01:00:00.000Z",
    "updatedAt": "2026-11-01T02:00:00.000Z",
    "holes": [{
      "par": 4,
      "long": 2,
      "short": 1,
      "putts": null,
      "obTee": 0,
      "obLater": 0,
      "direct": false,
      "tee": "left",
      "teeShort": true,
      "approach": ["short", "fat"]
    }]
  }]
}
```

`active` は0始まりの選択ホールです。`long / short / putts` は未入力の `null` または0〜30の整数、OBは0〜9の整数です。`tee` は `null / "straight" / "left" / "right"`、`teeShort` は `true / false / null` です。`null` は旧記録のショート有無不明を維持する値です。`approach` は未記録の `null`、ミスなしの `[]`、または `short / over / left / right / fat / thin` の重複なし配列です。`direct: true` のとき `short` は0です。目標の割合は0〜100の数値で保存します。IDは継続利用し、日時はタイムゾーン付きISO形式を使用します。

将来バージョンのスキーマは読み込まず、元の記録を維持します。ローカル保存データが壊れて読み込めない場合も上書きを止め、「JSON出力」で元データを `roundnote-recovery-YYYY-MM-DD.json` として救出できます。救出ファイルが復元可能なJSONかどうかは別途確認が必要です。

### バックアップ上の注意

Safariのサイトデータ削除、長期未使用、端末の容量不足などで、アプリのキャッシュやローカル記録が削除される場合があります。JSONはラウンド後に端末外にも保管してください。PNGは閲覧用で、JSON復元の代わりにはなりません。

JSONには日付・ゴルフ場名・プレー記録が含まれます。公開リポジトリには置かず、ローカルの `backups/` などで管理してください。`.gitignore` でExcelファイル、バックアップ用ディレクトリ、通常のJSONバックアップ名を除外しています。

## Excelへの取り込み・更新

PCにPython 3を用意し、依存ライブラリをインストールします。

```bash
python -m pip install -r requirements-excel.txt
```

アプリの「JSON出力」で保存したファイルを `backups/` に置き、次を実行します。

```bash
python scripts/import_rounds.py backups/roundnote-backup-2026-11-01.json --output outputs/roundnote.xlsx
```

ファイル名は手元のバックアップ名に置き換えてください。同じ出力先で再実行すると、Excel内の既存ラウンドとマージして更新します。Excelファイルを閉じてから実行してください。同一IDは更新日時が新しいものだけを反映し、同時刻・古いJSONで戻しません。別IDの記録は残します。

生成するシートは次の3つです。

| シート | 内容 |
| --- | --- |
| 分析ダッシュボード | スコア、OB方向別内訳、ティーショート率、50y以内2打以上率、パット、ボギーオン率の推移。直近5Rと前5Rの平均・変化 |
| ラウンド履歴 | 日付・ゴルフ場・終了状態・打数・対象数・率・OUT/INなどのラウンド単位の記録 |
| ホール別記録 | 18Hの打数、ティー方向とショート、直接ON、OB、振り返り、集計用の計算列 |

ダッシュボードは6つのExcelグラフを持ち、履歴の数式・値から更新されます。推移と直近5R比較は **終了済みかつ18H入力完了** のラウンドだけが対象です。途中・未終了ラウンドは履歴とホール別記録に残し、成長推移から除外します。

直近5Rと前5Rは、それぞれ最大5件です。比較する前の期間がなければ変化は空欄になります。打数・OBはラウンド平均、割合は対象数の合計を分母にした加重集計です。旧記録のショート有無不明はホール別記録でも空欄に保ち、ショート率の対象数から除外します。対象数0の率は0%にせず空欄、率の変化はパーセントポイント（pt）で表示します。ラウンド順は日付、作成日時の順です。

Excelには再取り込み用のラウンドJSONを履歴の非表示列に保持しています。取り込み時には3シートを再生成するため、Excelへの手修正や独自のグラフは置き換わります。Excelからアプリへ書き戻す機能はありません。元のJSONバックアップを保存し、独自分析は別ブックで行ってください。Excelファイルは公開Gitリポジトリの管理対象から除外しています。

## UIプレビュー

`http://localhost:8000/?preview=1` は通常の記録とは別の保存領域を使います。「サンプル」で18H入力済みの終了ラウンドを表示し、目標比較やPNGを試せます。入力を試す場合は結果の「記録を再開」を押してください。サンプルはお試しの現在ラウンドを置き換えます。

## テスト

アプリ・データモデル・オフラインのテスト：

```bash
node --test tests/core.test.cjs tests/app.test.cjs tests/offline.test.cjs
```

Excel取り込みのテスト：

```bash
python -m unittest discover -s tests -p test_excel_import.py -v
```

自動テストではティー方向とショートの選択、直接ONの分母除外、0と未入力、目標の良否反転、途中保存・再読み込み・終了、旧データ移行、同一ID更新、JSON検証、PNGの描画範囲、オフラインキャッシュ、Excelとの指標整合性を確認します。iPhone/Safariの表示・タッチ操作と、Excelアプリ固有の描画・再計算は、対象端末でも確認してください。

## ファイル構成

- `index.html`：静的エントリーポイント
- `app.css`：既存のグリーン基調のレスポンシブUI
- `app.js`：入力、画面遷移、保存、履歴、目標設定、JSON、PNG
- `roundnote-core.js`：スキーマ移行・検証、集計、目標比較、JSONマージ。ブラウザとNode.jsで利用
- `sw.js`：アプリ本体のオフラインキャッシュ
- `manifest.webmanifest`・アイコン：ホーム画面追加
- `scripts/preview.mjs`：ローカルプレビュー
- `scripts/import_rounds.py`：JSONと既存Excelをマージして分析ブックを生成
- `requirements-excel.txt`：Excel用Pythonライブラリ
- `tests/`：Node.jsとPythonの回帰テスト
